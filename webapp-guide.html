웹앱 만들기와 QR 안내 (학생용)

한눈에 보기

웹앱은 HTML 파일로 만들어 선생님께 제출하고, 선생님이 반 웹앱 사이트에 올려 주면 그 주소로 QR을 만들어 포스터에 붙여요. GitHub 가입은 필요 없어요.

  1. W1 노트북에서 예측 함수가 잘 되는지 확인해요.
  2. W2 제미나이에게 부탁해 index.html과 모델 파일을 만들고, 코랩에서 미리 열어 봐요.
  3. 제출 두 파일을 압축해 클래스룸에 내요.
  4. 선생님 반 웹앱 사이트에 올리고 내 주소를 알려 줘요.
  5. W3 받은 주소로 QR을 만들어 포스터 ⑦칸에 붙여요.

이렇게 올린 웹앱은 수업이 끝나도 계속 열려 있어서, 포스터를 붙여 두는 동안 누구나 QR로 써 볼 수 있어요. 내 노트북을 꺼도 괜찮아요.

따라 하기 캐러셀에 같은 내용이 한 장씩 정리되어 있어요.

W1 예측 함수 확인

W1은 노트북 안에서 predict_text()(사진 주제는 predict_photo())가 글 한 줄이나 사진 한 장을 받아 종류별 확률을 돌려주는지 확인하는 단계예요. 지금까지와 같아요.

  • 노트북의 W1 부탁 문장을 그대로 보내고 check("W1")을 통과해요.
  • 내가 직접 쓴 예시 3개를 넣어 보고, 틀린 결과가 있으면 메모해 두어요. 포스터와 보고서의 한계 칸에 쓸 수 있어요.

W2 HTML 웹앱 만들기

W2의 결과물은 webapp 폴더 하나예요. 그 안에 파일이 딱 두 개 들어 있어야 해요.

주제 webapp 폴더 안 파일 크기
글 분류 (재난문자, 글 자유 주제) index.html + model.json 보통 1MB 아래
사진 분류 (분리배출, 위성 사진, 사진 자유 주제) index.html + model.onnx 파일 하나에 25MB 아래

댓글 혐오 표현 주제는 공개 웹페이지를 만들지 않아요. 이 주제는 노트북의 그라디오 웹앱으로 수업 중에만 시연하고, 포스터 ⑦칸에는 QR 대신 화면 캡처를 붙여요.

글 주제: 제미나이에게 보낼 문장

[W2단계] 이미 있는 것: predict_text, vectorizer, model, class_names, INFO, PROJECT_TITLE, SHOW_EXAMPLES, texts_train, texts_test
인터넷 주소만 있으면 열리는 HTML 웹앱을 만들어 줘. 서버 없이 브라우저에서만 계산해야 해. ① webapp 폴더를 만들고 model.json을 이 모양으로 저장해 줘: {"title": PROJECT_TITLE, "classes": class_names, "info": INFO, "tfidf": {"analyzer": "char_wb", "ngram_range": [2, 3], "lowercase": true, "sublinear_tf": true, "norm": "l2", "vocabulary": {글자 조각: 번호}, "idf": [숫자들]}, "layers": [Dense 층마다 {"weights": [입력 수][출력 수] 2차원 리스트, "bias": [숫자들], "activation": "relu" 또는 "softmax"}], "examples": SHOW_EXAMPLES가 True면 texts_test 앞 3개(아니면 []), "tests": [texts_test 앞 5개마다 {"text": 글, "probs": predict_text의 확률(class_names 순서)}]}. 숫자는 소수 6자리로 반올림해 줘. ② webapp/index.html은 fetch('model.json')으로 읽고, 사이킷런 char_wb와 똑같이 글을 쪼개서(소문자로 바꾸고 띄어쓰기로 나눈 낱말 앞뒤에 공백을 붙여 2~3글자 조각, 낱말이 조각보다 짧으면 낱말 전체 하나만) 조각 수로 (1+ln(개수))×idf를 구하고 L2 정규화한 뒤 층을 차례로 계산해서, 가장 높은 종류와 INFO 안내, 종류별 확률 막대를 보여 줘. 페이지가 열리면 tests로 검산해서 화면 아래에 '검산 통과' 또는 '검산 실패'를 보여 줘. 서버, API 키, 다른 사이트의 그림은 쓰지 말고, 화면 아래에 '연습용 AI라 틀릴 수 있어요'를 넣어 줘. ③ 두 파일이 생겼는지 보여 줘.

1단계를 형태소 방식(ANALYZER = "word")으로 했다면 노트북 W2 카드의 두 번째 부탁을 보내요. 웹앱용 글자 조각 모델을 하나 더 학습해서 내보내요.

사진 주제: 제미나이에게 보낼 문장

[W2단계] 이미 있는 것: predict_photo, photo_features, BASE_MODEL, model, class_names, INFO, PROJECT_TITLE, paths_test
인터넷 주소만 있으면 휴대폰에서도 열리는 HTML 웹앱을 만들어 줘. 서버 없이 브라우저에서만 계산해야 해. ① 사진(높이×너비×3, 숫자 0~255)을 받아 photo_features와 똑같은 전처리 → 1단계의 base 모델 → 내 model까지 한 번에 계산하는 keras 모델 full을 만들고, !pip install -q tf2onnx onnxruntime 후 시험 사진 한 장으로 full.predict를 한 번 실행한 다음 full.export('webapp/model.onnx', format='onnx')로 저장해 줘. 입력 크기는 photo_features가 쓰는 크기로. ② paths_test 앞 3장으로 onnxruntime 결과와 predict_photo 결과가 같은지 비교해 줘. ③ webapp/index.html은 <script src='https://cdn.jsdelivr.net/npm/onnxruntime-web@1.20.1/dist/ort.min.js'>로 model.onnx를 읽고, 사진 고르기 버튼(input type=file, accept=image/*, 휴대폰은 카메라도)으로 사진을 받아 같은 크기로 줄인 뒤 0~255 숫자 [1, 높이, 너비, 3] float32로 넣어 계산해서, 가장 높은 종류와 INFO 안내, 종류별 확률 막대를 보여 줘. class_names(순서 그대로)와 INFO는 index.html 안에 넣어 줘. 사진은 어디에도 보내지 말고, 화면 아래에 '연습용 AI라 틀릴 수 있어요. 사람 얼굴은 올리지 마세요'를 넣어 줘. webapp 폴더에는 두 파일만 둬.

코랩에서 미리 열어 보기

내려받은 index.html을 더블클릭하면 모델을 못 읽어 빈 화면이 나와요. 예시 주제·자유 주제 노트북에서는 준비 칸에 도우미가 들어 있어서 preview_webapp() 한 줄이면 돼요. 노트북 밖에서는 아래 칸을 써요.

import subprocess
from google.colab import output
subprocess.Popen(["python", "-m", "http.server", "8000", "--directory", "webapp"])
output.serve_kernel_port_as_window(8000)
  • 검산 코드에서 파이썬과 웹의 확률 차이가 0.01 안쪽이면 통과예요.
  • 미리 보기 창에서 내 예시 3개를 넣어 W1과 같은 답이 나오는지 확인해요.

제출하기

webapp 폴더를 반-번호.zip 하나로 압축해 클래스룸 과제 "웹앱 제출"에 내요. 예: 2학년 1반 7번 → 2-1-07.zip

노트북에서는 make_zip("2-1-07") 한 줄이면 W2 확인, 압축, 내려받기까지 한 번에 해요. 노트북 밖에서는 아래처럼 해요.

MY_ID = "2-1-07"   # 반-번호 (번호는 두 자리)
import shutil, os
from google.colab import files
print(sorted(os.listdir("webapp")))   # index.html 과 model 파일 두 개만 있어야 해요
shutil.make_archive(MY_ID, "zip", "webapp")
files.download(MY_ID + ".zip")
확인할 것 기준
파일 이름 index.html(소문자), model.json 또는 model.onnx
파일 개수 딱 2개. 데이터 파일·사진·노트북은 넣지 않아요
크기 파일 하나에 25MB 아래
마감 포스터 제출 2일 전까지 (반별 날짜는 선생님 안내)

선생님이 올리기 전에 파일을 한 번 확인해요. 고쳐야 할 곳이 있으면 클래스룸 댓글로 알려 주고, 고친 파일을 같은 이름으로 다시 내면 돼요.

W3 주소 받고 QR 만들기

선생님이 올리면 내 웹앱 주소는 https://[선생님 아이디].github.io/[저장소 이름]/반-번호/ 모양이에요. 정확한 주소는 클래스룸으로 알려 줘요.

  1. 휴대폰과 컴퓨터에서 주소를 열어 웹앱이 동작하는지 확인해요.
  2. 코랩에서 아래 칸을 실행해 qr.png를 만들고 내려받아요.
  3. 휴대폰 카메라로 QR을 찍어 내 웹앱이 열리는지 한 번 더 확인해요.
  4. 포스터 ⑦칸에 QR을 넣고, 그 아래에 주소를 글자로도 적어요.
URL = "선생님이 알려 준 내 웹앱 주소"
!pip -q install qrcode
import qrcode
from google.colab import files
qrcode.make(URL, border=2, box_size=12).save("qr.png")
files.download("qr.png")

노트북 W3 카드의 부탁을 보내도 같은 코드를 만들어 줘요. 끝나면 check("W3")가 QR 안의 주소가 WEBAPP_URL과 같은지 확인해요.

A1 포스터에서 QR은 가로·세로 8cm 이상으로 크게 넣어야 포스터 앞에 선 친구들이 쉽게 찍을 수 있어요.

꼭 지킬 것

반 웹앱 사이트는 누구나 볼 수 있는 공개 사이트예요. 웹앱과 모델 파일에 아래 내용이 들어 있으면 올리지 않고 돌려보내요.

  • 이름 · 학교 이름 · 얼굴 사진 같은 개인정보
  • API 인증키 (웹앱은 키 없이 동작해야 해요)
  • 학습에 쓴 데이터 파일과 사진 (데이터는 다시 배포하지 않아요)
  • 인터넷에서 가져온 그림, 다른 사이트로 연결되는 링크
  • 혐오 표현이나 실제 사람을 가리키는 예시 문장

웹앱 화면에는 주제 제목, 사용법, 결과, '연습용 AI라 틀릴 수 있어요' 안내만 넣어요.

막힐 때

이럴 때 이렇게 해요
미리 보기 창이 빈 화면 webapp 폴더에 index.html과 모델 파일이 있는지 확인해요. 화면에서 우클릭 → 검사 → Console의 빨간 오류를 복사해 제미나이에게 "이 오류를 고쳐 줘"라고 보내요.
파이썬과 웹 확률이 다름 "검산에서 확률이 달라. 새로 학습하거나 전처리를 바꾸지 말고, 웹 계산을 파이썬과 똑같게 맞춰 줘"라고 보내요.
export "never called" 오류 W2 카드의 고치기 부탁을 보내요 (예측을 한 번 한 뒤 저장).
model.onnx가 25MB보다 큼 더 가벼운 BASE_MODEL(MobileNetV2 등)로 바꾸거나 선생님께 말해요.
tf2onnx 설치·변환 오류 오류 마지막 두 줄을 제미나이에게 보내요. 그래도 안 되면 선생님께 말해요.
주소를 열면 404 선생님이 올린 뒤 1~2분 기다려요. 주소의 반-번호, 대소문자, 끝의 /를 확인해요.
제출이 마감에 못 맞음 포스터 ⑦칸에 미리 보기 화면 캡처를 넣어요. 발표는 노트북 시연으로 해도 감점되지 않아요.
